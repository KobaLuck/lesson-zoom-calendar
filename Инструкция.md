# Урок: Zoom + Google Календарь + сообщение ученику

Одна кнопка создаёт Zoom-встречу, вставляет полученную ссылку участника в сообщение и добавляет урок в ваш Google Календарь. В событии сохраняются время, длительность, Zoom-ссылка и текст сообщения с доской. Никаких сообщений ученику программа сама не отправляет. Приглашения по email не рассылаются.

## Подключить Google Календарь — один раз

1. Откройте https://script.google.com/ под аккаунтом с вашим календарём и создайте проект «Урок — календарь».
2. Замените содержимое файла `Код.gs` содержимым файла **Google-Календарь.gs** из этой папки.
3. Слева рядом с **Сервисы** нажмите **+**, выберите **Google Calendar API**, версия **v3**, идентификатор **Calendar**, нажмите **Добавить**. Если проект использует отдельный Google Cloud-проект, включите в нём Calendar API тоже; для стандартного проекта Apps Script подключение обычно выполняется автоматически.
4. Откройте **Настройки проекта**, включите отображение файла манифеста **appsscript.json**. Вернитесь в редактор и замените содержимое этого файла нашим **appsscript.json**. Сохраните проект.
5. Выберите сверху функцию **setup** и нажмите **Выполнить**. Разрешите скрипту доступ к своему календарю. Это разрешение на чтение и изменение событий: оно нужно для создания урока и защиты от повторного добавления.
6. В журнале выполнения появится **Ключ для настроек приложения**. Скопируйте его в поле «Ключ Google-скрипта» программы. Не отправляйте ключ другим людям. Повторный запуск setup показывает прежний ключ, а не меняет его.
7. Нажмите **Развернуть → Новое развертывание → Тип → Веб-приложение**. Выполнять от имени: **Я**. У кого есть доступ: **Все / Anyone**. Разверните. Доступ к созданию событий защищён отдельным секретным ключом, который проверяется при каждом запросе. Если администратор Google Workspace запрещает доступ «Все», этот способ подключения потребует другого аккаунта или разрешения администратора.
8. Скопируйте адрес развертывания, заканчивающийся на **/exec**, в поле **Адрес Google-скрипта** в программе на Mac и на iPhone. Сохраните настройки на обоих устройствах.

Используется основной календарь аккаунта, которым развёрнут скрипт. Для другого календаря можно добавить в **Настройки проекта → Свойства скрипта** свойство **CALENDAR_ID** с ID календаря, к которому у этого аккаунта есть право записи. Не меняйте его, пока есть урок, ожидающий повторного добавления.

При изменениях кода Google-скрипта обновите развертывание через **Управление развертываниями → Изменить → Новая версия**. Простое сохранение кода не обновляет опубликованную версию. Сам Google-скрипт не получает ключей Zoom.

Официальные инструкции: [веб-приложения Apps Script](https://developers.google.com/apps-script/guides/web), [подключение расширенных сервисов](https://developers.google.com/apps-script/guides/services/advanced), [создание события](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert).

## Подключить Zoom — один раз

Если прежняя версия уже была настроена, сохранённые ключи используются автоматически.

1. Войдите в https://marketplace.zoom.us/ аккаунтом организатора.
2. Создайте **Server-to-Server OAuth App**. Заполните обязательную информацию о приложении и контактном лице.
3. Добавьте разрешение **meeting:write:meeting:admin** и активируйте приложение.
4. Введите **Account ID, Client ID, Client Secret** и email организатора в настройки программы. Секрет не пересылайте в чат. Пустые поля секретов сохраняют прежние значения.

[Документация Zoom](https://developers.zoom.us/docs/internal-apps/create/). Наличие сохранённых ключей ещё не означает, что сервис подтвердил их действительность. Проверка происходит при создании урока.

## Windows и Linux

Для Windows используйте **Запустить.bat**, для Linux — **Запустить.sh**. Нужен Python 3.9+; перед первым запуском создайте окружение и установите зависимости по разделу вашей ОС в **README.md**. Файлы программы должны находиться рядом.

Windows хранит ключи в системном диспетчере учётных данных. Linux использует Secret Service (например, GNOME Keyring): служба должна работать и быть разблокирована в пользовательском сеансе. Если хранилище недоступно, программа объяснит причину. На обеих системах сообщение копируется через браузер, а локальная история сохраняется в UTF-8 в `.lesson-zoom.json`. Настройки Zoom, Google-скрипта и порядок создания урока такие же, как на Mac.

## Mac

1. Дважды нажмите **Запустить.command**. Окно запуска оставьте открытым; его можно свернуть.
2. В браузере откроется локальная форма. Не открывайте HTML-файл отдельно. Нужен Python 3.9+; дополнительные пакеты не требуются.
3. Заполните настройки Zoom и Google-скрипта.
4. Выберите дату, время начала и длительность. Время урока вводится по Москве либо по Вьетнаму — смотрите выбранный пояс под часами.
5. Введите имя, предмет, обращение, часовой пояс ученика и тип урока. Для ученика по умолчанию выбрана **Москва**. В поле «С кем договорились?» укажите маму, папу или самого ученика.
6. При необходимости вставьте ссылку на конкретную доску **Миро** или **Холст** с доступом для ученика. Автоматического создания досок нет. Без ссылки блок про доску исчезает.
7. Прочитайте сообщение справа. Его можно править; сохраните метку **[ССЫЛКА ZOOM]**.
8. Нажмите **Создать Zoom, событие и сообщение**. После подтверждения сервисами появится готовый текст с настоящей Zoom-ссылкой.
9. Нажмите **Скопировать сообщение** и вставьте в переписку.

Если после ручной правки текста изменить данные урока, нажмите **Вернуть исходный текст** и внесите правки заново. Так имя и время не останутся от другого урока. Ручные правки действуют для текущего сообщения; редактирование постоянного шаблона через настройки пока не предусмотрено.

При запрете запуска скачанного файла попробуйте контекстное меню → «Открыть». Завершение программы — Ctrl+C в окне запуска. При необходимости назначьте файлу Запустить.command разрешение на выполнение.

## iPhone · Scriptable

1. Откройте **Урок-Zoom-Scriptable.js** и скопируйте весь текст.
2. В Scriptable замените содержимое старого скрипта этим текстом либо создайте новый скрипт.
3. Запустите его и заполните подключение Google-скрипта. Сохранённые ключи Zoom подхватятся из прежней версии.
4. Работа с формой такая же, как на Mac. Внешний HTML-файл на телефон переносить не нужно: он включён в скрипт.

Для обоих устройств используется одно развертывание Google-скрипта и один его ключ. Ученики, последние параметры и сообщения сохраняются отдельно на каждом устройстве; синхронизации списка учеников нет.

## Если Scriptable крутится и не показывает окно

Остановите скрипт и полностью замените его содержимое актуальным **Урок-Zoom-Scriptable.js**. В ранней версии обработчик формы начинал ожидание до открытия окна; этот порядок запуска исправлен. Сохранённые настройки остаются в Keychain, переустанавливать Scriptable не нужно.

Запускайте скрипт непосредственно внутри приложения Scriptable. На старте используются только локальные данные; загрузки Zoom или Google до появления формы нет. Если окно всё равно не открывается, пришлите текст ошибки из Scriptable и версию iOS. Проверка механизма запуска включена в тесты, но окончательная проверка нужна на настоящем iPhone.

## Если произошла ошибка

**Zoom создался, а календарь не подтвердил добавление:** сообщение и Zoom-ссылка уже сохранены. Проверьте подключение и нажмите **Повторить добавление в календарь**. Новая Zoom-встреча не создаётся. Если вы закрыли программу, откройте **Последнее сообщение** и повторите добавление оттуда. Пока этот шаг не завершён, создание следующего урока блокируется, чтобы не потерять данные предыдущего.

Google-скрипт использует один и тот же ID события для одного запроса. Если событие добавилось, а ответ потерялся, повторное обращение находит его по ID. Если вы вручную удалили такое событие, восстановите его в календаре, прежде чем повторять запрос.

**Zoom не подтвердил создание из-за сетевой ошибки или ошибки сервера:** сначала проверьте список встреч в Zoom. Автоматический повтор того же запроса блокируется. Изменение данных урока или открытие новой формы может создать другой запрос, поэтому сначала убедитесь, что прежней встречи нет.

**Календарь не подключается:** проверьте окончание адреса **/exec**, доступ **Все**, запуск от имени владельца и ключ. После смены Google-аккаунта или разрешений может понадобиться повторный запуск setup и обновление развертывания.

Ключи хранятся в системном хранилище устройства: Keychain на Mac/iPhone, Windows Credential Locker на Windows и Secret Service на Linux. Последнее сообщение и список учеников на Mac находятся в скрытом файле **.lesson-zoom.json** рядом с программой; на iPhone — в Keychain Scriptable. Файл состояния Mac содержит ссылки на уроки: не публикуйте его.

Тарифные ограничения Zoom сохраняются. Длительность в форме не снимает лимиты аккаунта.

## Эмодзи и ссылки в Telegram

Обычные **😤 🤪 🥰** сохраняются при копировании. Кастомные эмодзи Telegram требуют специальных сущностей сообщения и не передаются через буфер обычного текста. Их можно вставить вручную после вставки сообщения в Telegram. [Документация Telegram](https://core.telegram.org/api/custom-emoji).

При копировании используются полные ссылки: они распознаются Telegram как ссылки. Подписи вида «Ссылка на Миро» с URL, спрятанным внутри названия, обычный текстовый буфер не сохраняет.

## Что проверено

Проверены на имитациях ответов сервисов: создание Zoom, подстановка ссылки и кода, добавление календарного события, восстановление после ошибки Google без второй Zoom-встречи, защита Google-скрипта ключом и повторные запросы без второго события. Проверены московское время, другой пояс ученика, разные даты в двух поясах, обращения и необязательная доска. Форму просмотрели и использовали в браузере с тестовым обработчиком.

Настоящие встречи и календарные события при проверке не создавались. Для окончательной проверки требуется однократное подключение аккаунтов и пробный запуск. Версия Scriptable проверена вне iPhone на имитациях его функций; запуск на настоящем устройстве ещё требуется.
